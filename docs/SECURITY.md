# Security and Responsible Use

## Intended Use

- Defensive security research
- Smart-contract auditing education
- Honeypot detection/analysis
- Controlled test-environment experimentation

## Prohibited Use

- Deploying contracts to deceive users or steal funds
- Misrepresenting malicious contracts as safe investments
- Using scanner-evasion techniques for fraud

## Safe Handling

- Analyze in isolated local/fork environments.
- Never connect wallets holding real funds.
- Treat all privileged functions (owner, mint, blacklist, whitelist, mode switch) as high risk until verified.
- Validate behavior with code review and dynamic testing; do not trust labels.
